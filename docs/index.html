Mighty Crew

A crew of coding-agent sessions on one codebase: one role per working tree, a shared board every role reads at start, and messages between roles. One binary, crew.

Download the latest release Source on GitHub Read the specification

Four things go wrong when you run several agents by hand

Two writers in one checkout

A session and a fork of it edit the same tree; one's uncommitted changes sit under the other's test run and commit.

Nobody knows what the others decided

A default changed in one session reaches another only when you retype it.

Messages held and expired

A line sent across permission modes waits for an approval that never comes.

A reboot forgets everything

Which directory belonged to whom lived in your head and your terminal history.

Tools that run agents in worktrees solve the first and the fourth. Mighty Crew's contribution is the second and the third: the board and the messages, with the launcher as the carrier.

A day with a crew

crew start product        # the product role's agent, in its own tree, with the board in front of it
crew note "release branch prepared; cut after night 2"
crew msg engine "the API spec moved; section 7 is yours"
crew status               # every role: tree, branch, head, running or idle, activity, last note

The board is one Markdown file in a repository the crew already pushes to. Every role appends a dated line through a small clone of its own, so no working tree is touched, and every session starts with the last lines in its context. Nothing a role writes is an instruction, and nothing counts as your approval.

Install

# Linux and macOS: the release binary into ~/.local/bin (Windows: install.ps1)
curl -fsSL https://raw.githubusercontent.com/dreamference/mighty-crew/main/install.sh | sh

# anywhere else: from source (Rust stable)
git clone https://github.com/dreamference/mighty-crew.git && cd mighty-crew
cargo build --release && install -m 755 target/release/crew ~/.local/bin/crew

# then, in the repository that will hold the board
crew init              # writes ~/.config/mighty-crew/crew.toml; add one [roles.<name>] table per role
crew install-hook      # every session in a role's tree starts with the board; /crew works inside sessions
crew doctor            # what is missing, with the fix

The commands

CommandWhat it does
crew start <role>Start or resume the role's agent in its tree, with its charter and the board's tail; refuses a tree where a session already runs.
crew open <role>The same, in a new terminal window.
crew boardThe board's last lines; --for <role>, --tag done, --decisions.
crew note "…"Append a dated line as the role whose tree you are in.
crew msg <role> "…"Send a line to that role's running session, with its twin on the board first.
crew statusEvery role: tree, branch, head, session state, commits since its last note, what it is doing now, last note.
crew doctorThe configuration, the trees, the sessions, the board, the hook, each finding with its fix.
crew install-hookThe SessionStart hook that prints the board, and the /crew skill.
crew ask "…" --options a,b,cA decision for you, on the board: answer with crew answer <id> <option>, or tick the box on GitHub from your phone; crew board --pending lists them.
crew now "…"What a role is doing right now; crew status shows it.
crew resource <name> "…"A shared resource and its rules, on the board where every role reads them.
crew handoff <role> <path>Data for another role through a neutral folder, never its tree.
crew upFrom a clone to a live crew: every role in a tmux window, or a terminal each.

What it is not

No orchestrator, no task queue, no lead role, no service or daemon, no polling loop that costs a model turn. Roles are peers; you decide what each does next, by talking to it or by writing on the board. The MVP runs Claude Code sessions; other agents follow.

AGPL-3.0, as Mightling. Built from one day of running four sessions by hand; the specification keeps every lesson with the incident it came from.
